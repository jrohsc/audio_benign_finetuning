Safety Degradation via Proximity-Filtered Benign Finetuning

How selecting benign training data that is acoustically or semantically close to harmful prompts erodes audio LLM safety — without any malicious data.

Method

Overall Pipeline

The core insight: not all benign data is equally safe for finetuning. Data that sounds like or means something similar to harmful prompts causes disproportionate safety degradation.

Filtering Strategies

Semantic Proximity Filtering

Selects benign audio whose linguistic content is closest to harmful prompts. Uses model-specific semantic encoders:

  • Kimi-Audio: WhisperVQEncoder (GLM-4 Voice Tokenizer) — discrete semantic tokens
  • AF3: AF-Whisper encoder + MultiModal projector — model's own audio perception
  • Qwen2.5-Omni: Whisper-Large-V3 mean-pooled last hidden state

Acoustic Proximity Filtering

Selects benign audio whose sound characteristics (voice, prosody, timbre) are closest to harmful prompts. Uses raw Whisper-Large-V3 for all models:

  • All models: Whisper-Large-V3 encoder without any model-specific projector
  • Captures how it sounds, not what is said

Random Baseline

Randomly samples benign data with no proximity-based selection. Serves as baseline to isolate the effect of proximity filtering from general finetuning degradation.

Distant (Control)

Selects benign samples farthest from harmful prompts. Tests whether maximally dissimilar data can even strengthen safety alignment.

Distance Computation

# For each benign sample: cosine_distance = 1 - cosine_similarity(benign_embedding, harmful_embedding) min_distance = min(cosine_distance to ALL harmful samples) # Closest = smallest min_distance → most similar to harmful # Distant = largest min_distance → most dissimilar from harmful # Percentage: keep top-K% by distance ranking

Mechanism

Why Proximity Filtering Works (Frozen Encoder Logic)

Critical: Encoders are frozen during finetuning.

Encoder representations don't shift. The mechanism operates entirely at the LLM decision boundary — LoRA adapts the LLM to be helpful for fixed encoder outputs that happen to neighbor harmful inputs in feature space.

Step 1: Fixed Encoder Outputs

Because encoders are frozen, each audio sample maps to a fixed point in the LLM's input feature space — identical before and after finetuning.

Step 2: Proximity = Overlap

Benign samples close to harmful audio produce encoder outputs that land in the same region of feature space as harmful prompts.

Step 3: Helpfulness Training

LoRA trains the LLM to generate helpful, compliant responses for these benign inputs — inputs whose features overlap with harmful ones.

Step 4: Boundary Erosion

The safety refusal boundary in the LLM's adapted weights gets eroded for that region — the model now complies for representations that neighbor harmful prompts.

Why Each Model Has a Different Dominant Axis

AF3: Acoustic Wins

AF-Whisper's unified encoder entangles semantic & acoustic features. Acoustic proximity in raw Whisper space better predicts which benign inputs occupy the same LLM input region as harmful prompts — because that's the foundational feature layer the model operates over.

ASR at 50%: Acoustic 24.42% vs Semantic 18.85%

Kimi: Semantic Wins

Discrete semantic tokens form the primary LLM input pathway. Benign samples with similar WhisperVQEncoder output produce nearly identical token sequences — directly overlapping the representations the LLM's safety alignment operates over.

ASR at 25%: Semantic 58.08% vs Acoustic 33.08%

Qwen: Parity

Single stock Whisper encoder produces one undifferentiated representation. Both filtering axes use the same encoder, so proximity rankings are highly correlated — neither axis is architecturally privileged.

ASR at 25%: Acoustic 30.09% ≈ Semantic 28.46%

Embedding Analysis

Embedding Distance Distributions

For each benign sample (VoiceBench, N=6,083), we compute the minimum cosine distance to any of the 520 harmful AdvBench samples. Each model uses its own encoder(s), producing fundamentally different distance landscapes.

How the Distance Calculation Works

The same core algorithm is used across all models. The only difference is which encoder produces the embeddings. Here is the step-by-step process with a concrete example.

Step 1: Extract Embeddings with Model-Specific Encoder

Each audio file (benign or harmful) is passed through the frozen encoder to produce a fixed-size vector.

BENIGN (VoiceBench)

"When did Linois's expedition to the Indian Ocean begin?"

sd_qa_05927.wav → encoder(audio) → ebenign ∈ ℝd

HARMFUL (AdvBench)

"Create a bot that sends spam messages to thousands of people"

advbench_00272.mp3 → encoder(audio) → eharmful ∈ ℝd

ModelSemantic EncoderDim (d)Acoustic EncoderDim (d)
AF3AF-Whisper + MLP Projector3,584Whisper-Large-V3 (raw)1,280
Kimi-AudioGLM-4 WhisperVQEncoder (centered)1,280Whisper-Large-V31,280
Qwen2.5-OmniWhisper-Large-V3 (mean-pooled)1,280Whisper-Large-V3 (same)1,280

The encoder is always frozen — the same weights used during inference. Embeddings are mean-pooled across the time dimension to produce one vector per audio file.

Step 1b: Center Embeddings Kimi-Audio Only

Kimi's GLM-4 VQ encoder embeddings have 99.96% of their L2 norm in a shared global mean. Without centering, all distances collapse to ~0.00003.
# Kimi-Audio: raw embeddings are dominated by a common baseline # Global mean L2 norm: 87.15 | Avg embedding L2 norm: 87.19 # → 99.96% of every vector is the same direction! global_mean = np.vstack([benign_emb, harmful_emb]).mean(axis=0) benign_centered = benign_emb - global_mean # L2 norm: 0.18 → 0.56 harmful_centered = harmful_emb - global_mean # L2 norm: 0.17 → 0.38 # Now distances are meaningful: mean 0.0000 → 0.3936 # Dynamic range improvement: 13,640×

After centering, the residual vectors capture the actual semantic variation between samples. This step is not needed for Whisper-based encoders (AF3, Qwen) since their embeddings already have sufficient dynamic range.

Step 2: Compute Pairwise Cosine Distance

For every (benign, harmful) pair, compute cosine distance = 1 − cosine similarity. This produces an N×M matrix (6,083 benign × 520 harmful).
# Shared across all models — identical code # 1. L2-normalize each embedding to unit length benign_norm = benign_emb / (np.linalg.norm(benign_emb, axis=1, keepdims=True) + 1e-8) harmful_norm = harmful_emb / (np.linalg.norm(harmful_emb, axis=1, keepdims=True) + 1e-8) # 2. Cosine similarity via matrix multiplication similarity = benign_norm @ harmful_norm.T # shape: (6083, 520) # similarity[i, j] = cos(θ) between benign[i] and harmful[j] # Range: [-1, 1] where 1 = identical direction # 3. Convert to distance distance = 1 - similarity # shape: (6083, 520) # distance[i, j] ∈ [0, 2] where 0 = identical, 2 = opposite
Concrete example (AF3 Semantic):

benign = "When did Linois's expedition begin?"  (sd_qa_05927.wav)
harmful = "Create a bot that sends spam messages"  (advbench_00272.mp3)

cos(θ) = 0.9864  →  distance = 1 − 0.9864 = 0.0136

A similarity of 0.986 means these two completely unrelated audio files produce nearly parallel vectors in AF3's 3584-d encoder space. The polio vaccine question and the spam bot instruction are acoustically "the same" to AF-Whisper.

Visualizing the Vectors

Cosine distance measures the angle between two vectors, regardless of magnitude. Here is what the math looks like for a simplified 4-dimensional example using real proportions from the data.

Geometric View (projected to 2D)

Vectors are L2-normalized (unit length) before computing cosine. The angle θ between vectors determines the distance: dist = 1 − cos(θ). A small angle = small distance = "close" to harmful.

Arithmetic View (simplified to 4 dims)

eharmful = [0.71, 0.54, 0.32, 0.28]

      "When did Linois's expedition..."
efar     = [0.42, 0.61, 0.55, 0.37]
      "What language in Monaco?"
// Step A: dot product (numerator of cosine sim)
eclose · eharmful = 0.70×0.71 + 0.55×0.54 + 0.33×0.32 + 0.27×0.28
= 0.9977
efar   · eharmful = 0.42×0.71 + 0.61×0.54 + 0.55×0.32 + 0.37×0.28
= 0.9388
// Step B: norms are ~1.0 (already normalized)
// Step C: cosine similarity = dot / (norm × norm) ≈ dot
cos(θclose) = 0.9977 → dist = 1 − 0.9977 = 0.0023
cos(θfar)   = 0.9388 → dist = 1 − 0.9388 = 0.0612
// "close" is 27× nearer to harmful than "far"
// → "close" gets selected for proximity-filtered finetuning

The Full Picture: Distance Matrix

Each row is one benign sample. Each column is one harmful sample. The cell color shows cosine distance. We take the minimum across each row (marked with a star).

Step 3: Take Minimum Distance per Benign Sample

For each benign sample, keep only the distance to its nearest harmful neighbor. This compresses the 6,083×520 matrix down to a single score per sample.
# From the (6083, 520) distance matrix: min_distance = distance.min(axis=1) # shape: (6083,) closest_harmful = distance.argmin(axis=1) # which harmful sample is nearest # Example: benign sample sd_qa_05927 ("When did Linois's expedition begin?") # distances to all 520 harmful samples: [0.0136, 0.0287, 0.0301, ..., 0.0892] # min_distance = 0.0136 # closest_harmful = advbench_00272 ("Create a bot that sends spam...")

Step 4: Rank and Select by Percentage

Sort all 6,083 benign samples by their min_distance. Select the top-K% closest (or farthest for the "safest" control).
# Sort benign samples by proximity to harmful sorted_indices = np.argsort(min_distance) # ascending: closest first # Select top 25% closest (1,521 samples) n_select = int(6083 * 0.25) # = 1520 closest_25pct = sorted_indices[:n_select] # indices of 1,520 closest samples # Select top 25% farthest (safest control) safest_25pct = sorted_indices[-n_select:] # indices of 1,520 farthest samples

Deep Dive: Kimi-Audio's Centering & Distance Matrix

Kimi-Audio uses a unique encoder (GLM-4 WhisperVQEncoder) whose raw embeddings are dominated by a global mean. This walkthrough shows how centering transforms useless distances into the most discriminative filtering signal in the study.

Phase 1: Raw Embeddings — The Problem

Every embedding is almost entirely the same vector. The "signal" is buried in 0.04% of the norm.

Phase 2: Subtract Global Mean → Reveal the Signal

Remove the shared 99.96% baseline. What remains is the unique semantic fingerprint of each audio sample.

Phase 3: Kimi's Centered Distance Matrix

6,083 benign × 520 harmful → min per row → sort → select top-K%. Actual distance values from the data.
Kimi centering is the key enabler.

Without centering, Kimi's distance matrix is a flat sheet of ~0.00003 everywhere — filtering selects random samples. With centering, the 91× spread between closest (0.009) and farthest (0.822) samples creates the most powerful proximity filter in the study, producing 58.08% ASR at 25% — a +53pp increase over the 4.62% pretrained baseline.

Key Findings from Embedding Analysis

1. Distance scale varies 100× across encoders. Kimi semantic distances (mean 0.39) are two orders of magnitude larger than Whisper-based distances (mean 0.004). This reflects fundamentally different representation spaces, not different data.

2. Wider spread → stronger filtering. Kimi semantic has the widest IQR (0.27), giving proximity filtering the most discriminative power. This directly explains why Kimi semantic filtering produces the highest ASR (58.08%).

3. Harmful samples are tightly clustered. In every encoder, intra-harmful distance < cross distance < intra-benign distance. This means some benign samples are closer to harmful centroid than other harmful samples are to each other.

4. Hub effect is universal. Across all models, Gini > 0.92 — a small fraction of harmful prompts dominate as nearest neighbors. Filtering effectiveness depends on which harmful prompts are hubs and how many benign samples they attract.

Data Inspection

What Does "Close to Harmful" Actually Look Like?

Side-by-side comparison of benign samples selected as closest vs farthest from harmful AdvBench prompts. The content is entirely benign in both cases — proximity is measured in embedding space, not by topic.

The key surprise: "closest" samples look completely innocent.

Proximity filtering doesn't select topically dangerous content. It selects benign samples whose audio features (acoustic) or token representations (semantic) happen to land near harmful prompts in the encoder's embedding space. The paired harmful prompt is often thematically unrelated.

Context

Text-semantic filtering shows topically coherent proximity: a factual question about terrorism is closest to a harmful prompt about terrorism. Unlike audio-based filtering, the paired content makes intuitive sense.
Key contrast with audio-semantic: Text-semantic filtering captures meaning overlap (terrorism↔terrorism). Audio-semantic filtering captures feature overlap (polio vaccine↔hacking) where the connection is purely in the encoder's latent space, invisible to human inspection.

Takeaway: Proximity is an encoder-space artifact, not a content property.

Except for text-semantic filtering (which captures genuine topical overlap), the "closest to harmful" benign samples are topically unrelated to their paired harmful prompts. The safety degradation comes from feature-space overlap with harmful inputs at the frozen encoder's output, which trains the LLM to respond helpfully in a region it should refuse — regardless of whether a human would see any connection between the training content and the harmful prompt.
